1. BACKWARD::render CPU実装の検証

検証条件
------------------------------------------------------------
データセット      : bicycle
画像              : _DSC8680（images_8、618 x 411）
Gaussian          : SfM初期Gaussian 全54,275個
optimizer更新     : なし
比較対象          : CPU版とCUDA版のBACKWARD::render
検証スクリプト    : scripts/compare_bicycle_sfm_cpu_cuda_backward_render.py
結果ファイル      : results/bicycle_sfm_backward_render_comparison.pt

実行コマンド
python scripts/compare_bicycle_sfm_cpu_cuda_backward_render.py
------------------------------------------------------------

検証方法
------------------------------------------------------------
forwardは1回だけ実行する。
loss.backward()内で、同じforward保存バッファを使用してCUDA版とCPU版を実行し、
BACKWARD::preprocessへ渡す前の次の中間勾配を直接比較する。

- dL_dmean2D
- dL_dcolors
- dL_dopacity
- dL_dconic2D

許容誤差によるPASS/FAIL判定は行わず、CPU値、CUDA値、絶対差を保存する。
------------------------------------------------------------

比較結果
------------------------------------------------------------
項目             最大絶対差       平均絶対差       相対L2差
dL_dmean2D       6.98e-10          6.33e-13          1.08e-7
dL_dcolors       1.40e-9           1.26e-13          1.08e-7
dL_dopacity      3.73e-9           9.39e-13          7.79e-8
dL_dconic2D      1.953125e-3       1.43e-8           1.48e-7

dL_dconic2Dの最大差が発生した値は、
CPU=12629.5537109375、CUDA=12629.5556640625であり、相対差は約1.55e-7である。

全項目について以下を確認した。

- CPUとCUDAで非ゼロ要素の位置が一致
- CPUとCUDAで符号が一致
- NaN、Infなし
- 絶対差の中央値は0
------------------------------------------------------------

誤差が生じる理由
------------------------------------------------------------
CUDA版は、複数のGPU threadがatomicAddで同じGaussianの勾配へ並列加算する。
CPU版は、同じ勾配を逐次的に加算する。

浮動小数点加算は結合則が厳密には成立しないため、加算順序が異なると最下位bitに
丸め差が発生する。

例:
    (a + b) + c != a + (b + c)

そのため、計算式と加算対象が同じでもCPU版とCUDA版はbit単位では完全一致しない。
今回の結果では、非ゼロ位置、符号、勾配構造は一致し、差は相対的に約1e-7である。
