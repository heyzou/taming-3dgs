1. BACKWARD::render CPU実装の検証

検証条件
------------------------------------------------------------
データセット      : bicycle
画像              : _DSC8680（images_8、618 x 411）
Gaussian          : SfM初期Gaussian 全54,275個
optimizer更新     : なし
比較対象          : CPU版とCUDA版のBACKWARD::render
検証スクリプト    : scripts/compare_bicycle_sfm_cpu_cuda_backward_render.py
結果ファイル      : results/bicycle_sfm_backward_render_comparison.pt

実行コマンド
python scripts/compare_bicycle_sfm_cpu_cuda_backward_render.py
------------------------------------------------------------

検証方法
------------------------------------------------------------
forwardは1回だけ実行する。
loss.backward()内で、同じforward保存バッファを使用してCUDA版とCPU版を実行し、
BACKWARD::preprocessへ渡す前の次の中間勾配を直接比較する。

- dL_dmean2D
- dL_dcolors
- dL_dopacity
- dL_dconic2D

許容誤差によるPASS/FAIL判定は行わず、CPU値、CUDA値、絶対差を保存する。
------------------------------------------------------------

比較結果
------------------------------------------------------------
項目             最大絶対差       平均絶対差       相対L2差
dL_dmean2D       6.98e-10          6.33e-13          1.08e-7
dL_dcolors       1.40e-9           1.26e-13          1.08e-7
dL_dopacity      3.73e-9           9.39e-13          7.79e-8
dL_dconic2D      1.953125e-3       1.43e-8           1.48e-7

dL_dconic2Dの最大差が発生した値は、
CPU=12629.5537109375、CUDA=12629.5556640625であり、相対差は約1.55e-7である。

全項目について以下を確認した。

- CPUとCUDAで非ゼロ要素の位置が一致
- CPUとCUDAで符号が一致
- NaN、Infなし
- 絶対差の中央値は0
------------------------------------------------------------

誤差が生じる理由
------------------------------------------------------------
CUDA版は、複数のGPU threadがatomicAddで同じGaussianの勾配へ並列加算する。
CPU版は、同じ勾配を逐次的に加算する。

浮動小数点加算は結合則が厳密には成立しないため、加算順序が異なると最下位bitに
丸め差が発生する。

例:
    (a + b) + c != a + (b + c)

そのため、計算式と加算対象が同じでもCPU版とCUDA版はbit単位では完全一致しない。
今回の結果では、非ゼロ位置、符号、勾配構造は一致し、差は相対的に約1e-7である。
------------------------------------------------------------

2. BACKWARD::render_cpuのボトルネック計測

計測方法
------------------------------------------------------------
ビルド設定は「-O3 -g」とする。

- -O3 : 実運用と同じコンパイラ最適化を有効にする
- -g  : CPU命令をbackward_cpu.cppのソース行と対応させる

大きな処理区間はC++標準ライブラリのstd::chronoで実時間を計測する。

- GPUからCPUへのデータ転送
- CPU上の勾配配列初期化
- render_cpu全体
- CPUからGPUへの勾配転送

render_cpu内部にはchronoを入れず、元の1ループを維持する。
Nsight SystemsのCPUサンプリングを次の14区間へ分類する。

1. Tile / pixel preparation
2. Gaussian preparation
3. Pixel eligibility check
4. Gaussian exponent（dx、dy、power）
5. Gaussian weight（exp）
6. Alpha calculation
7. Alpha threshold
8. Color gradient
9. Foreground alpha gradient
10. Background alpha gradient
11. Transmittance update
12. Mean gradient
13. Conic / opacity gradient
14. Output accumulation

各区間の時間は次の式で推定し、時間の大きい順にCSVへ出力する。

区間の推定時間 = render_cpu時間の中央値 × 区間のサンプル数 / 全サンプル数

出力項目は、順位、区間名、サンプル数、割合、推定時間、実行回数、
1回あたりの推定時間とする。

処理量を確認するため、次の実行回数もカウントする。

- bucket数
- Gaussian x pixel試行回数
- exp実行回数
- alphaでスキップした回数
- 実際に勾配計算した回数

pixelごとのchronoやNVTXは計測負荷が大きいため使用しない。
全体時間はchrono、内部割合はCPUサンプリング、処理量はカウンターで確認する。

実行方法
------------------------------------------------------------
1. C++拡張を再ビルドする。

cd submodules/diff-gaussian-rasterization
TORCH_CUDA_ARCH_LIST=8.7 python setup.py build_ext --inplace
cd ../..

2. chronoとカウンターを5回計測する。

bash scripts/profile_bicycle_cpu_backward_render.sh

出力:
results/bicycle_cpu_backward_render_profile.csv

3. Nsight Systemsで20回サンプリングする。

bash scripts/sample_bicycle_cpu_backward_render.sh

このスクリプトはNsight計測後、14区間の解析と画像生成も実行する。

出力:

- results/bicycle_cpu_backward_render_nsys.nsys-rep
- results/bicycle_cpu_backward_render_sections.csv
- results/bicycle_cpu_backward_render_profile.png

デフォルトの計測条件:

- bicycleのimages_8
- 固定画像1枚
- SfM初期Gaussian全数
- optimizer更新なし
- ウォームアップ1回
- chrono計測5回
- Nsightサンプリング20回

ウォームアップは初回初期化の影響を除くための1回で、結果には含めない。
chronoは5回の中央値、内部区間は20回分のCPUサンプル割合を使用する。

計測結果
------------------------------------------------------------
14区間版、5回のchrono中央値:

- 全体: 1211.08 ms
- GPU -> CPU転送: 46.30 ms
- CPU勾配配列初期化: 3.12 ms
- render_cpu: 1160.45 ms
- CPU -> GPU転送: 0.794 ms

Nsightサンプルから求めたrender_cpu内部の推定時間（降順）:

1. Gaussian exponent: 427.76 ms（36.86%）
2. Alpha threshold: 390.81 ms（33.68%）
3. Gaussian weight: 81.78 ms（7.05%）
4. Foreground alpha gradient: 59.84 ms（5.16%）
5. Pixel eligibility check: 47.79 ms（4.12%）
6. Alpha calculation: 45.71 ms（3.94%）
7. Mean gradient: 25.10 ms（2.16%）
8. Tile / pixel preparation: 23.16 ms（2.00%）
9. Output accumulation: 16.11 ms（1.39%）
10. Background alpha gradient: 12.43 ms（1.07%）
11. Conic / opacity gradient: 10.43 ms（0.90%）
12. Color gradient: 9.43 ms（0.81%）
13. Gaussian preparation: 8.09 ms（0.70%）
14. Transmittance update: 2.02 ms（0.17%）

最大のボトルネックはGaussian exponentで、次がAlpha thresholdである。
この2区間でrender_cpuの約70.54%を占める。
